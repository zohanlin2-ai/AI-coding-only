UML Architecture Details & Decision Rationale

Sequence & Activity Diagram Rationale

Both models represent distinct dimensions of the system design to make cross-component interactions and internal logic understandable:

  • Go Game Loop Sequence Diagram: Details how events flow asynchronously between the UI rendering surface (`GoBoard.tsx`), game orchestrator state (`App.tsx`), rules engine validator (`goEngine.ts`), and external API client integrations (`aiService.ts`).
  • Overall App Lifecycle Activity Diagram: Captures the system's complete behavioral pipeline from pre-game configuration, live coordinate validations, turn switching logic, up to scoring overlay and SGF file serialization.
  • MCTS Algorithm Activity Diagram: Formally models the iterative Monte Carlo Tree Search optimization workflow, emphasizing progressive heuristic node evaluation and randomized, capture-biased rollout simulations.

Advanced Offline MCTS Techniques

The client-side search engine implements advanced heuristics to enable strong play in browser JS within 1-2 seconds per move:

  • Progressive Bias Formula: Integrates domain-specific heuristics `heuristicScore / (10 * (visits + 1))` into UCB1 selection. Guides early search iterations towards high-value shape intersections before raw simulations are accumulated.
  • Capture-Biased Playouts: During randomized simulations (playouts), the agent detects state capture opportunities, triggering capturing moves with a 60% probability check to improve evaluation accuracy.
